title: Rules
description: Memberikan instruksi project dan aturan kerja khusus kepada Mage.
---

Rules membantu Mage memahami struktur project, command penting, coding convention, dan batasan yang harus diikuti. Mage membaca `AGENTS.md` sebelum mengerjakan task.

## Inisialisasi

Jalankan `/init` dari TUI untuk menganalisis project dan membuat atau memperbarui `AGENTS.md`.

```text frame="none"
/init
```

Commit `AGENTS.md` ke Git agar seluruh tim memakai instruksi yang sama.

## Contoh

```md title="AGENTS.md"
# TypeScript Project

## Project structure

- `packages/api`: backend service
- `packages/web`: frontend application
- `packages/shared`: shared types and utilities

## Coding standards

- Use TypeScript strict mode
- Run `bun test` from the changed package
- Use conventional commits

## Monorepo conventions

- Import internal packages through workspace names
- Do not run tests from the repository root
```

Instruksi yang spesifik dan dapat dijalankan lebih berguna daripada deskripsi panjang tentang project.

## Jenis rules

### Project

Letakkan `AGENTS.md` di root project. Rules ini berlaku untuk project dan aman disimpan bersama source code.

### Global

Letakkan rules pribadi di `~/.mage/AGENTS.md`. Gunakan untuk preferensi yang berlaku pada semua sesi, bukan convention milik satu repository.

## Prioritas

Mage menggabungkan rules dari global config, root project, dan direktori yang lebih dekat dengan file aktif. Instruksi yang paling spesifik mengambil prioritas saat terjadi konflik.

```text
~/.mage/AGENTS.md
project/AGENTS.md
project/packages/web/AGENTS.md
```

Dengan struktur tersebut, file di `packages/web` mengikuti ketiga rules dan aturan lokal `packages/web/AGENTS.md` menjadi yang paling spesifik.

## Custom instructions

Tambahkan file instruksi lain melalui `instructions` di `~/.mage/mage.json`.

```json title="~/.mage/mage.json"
{
  "instructions": [
    "docs/development.md",
    "packages/*/AGENTS.md"
  ]
}
```

Path dapat berupa file langsung atau glob. Gunakan ini untuk dokumen yang sudah ada dan tidak perlu disalin ke `AGENTS.md`.

## Referensi file eksternal

`AGENTS.md` dapat menunjuk ke file lain dengan sintaks `@path/to/file.md`. Tulis instruksi secara eksplisit agar agent mengetahui kapan file tersebut harus dibaca.

```md title="AGENTS.md"
Saat mengubah API, baca @docs/api-conventions.md.
Saat membuat migration, baca @docs/database.md.
```

Gunakan reference yang relevan dengan task. Memuat seluruh handbook pada setiap sesi hanya menghabiskan context.

## Pedoman isi

- Cantumkan command build, test, lint, dan typecheck yang benar.
- Jelaskan lokasi package penting serta ownership-nya.
- Tulis larangan yang melindungi data, security, dan compatibility.
- Hindari aturan yang sudah ditegakkan formatter atau compiler.
- Perbarui rules ketika workflow project berubah.
