**Qwen3.6 27b** adalah model yang digunakan Mage melalui GAIA. Kualitas keluaran model sangat bergantung pada kualitas prompt yang diberikan. Prompt yang jelas dan terstruktur menghasilkan kode yang lebih akurat, lebih sedikit perubahan yang tidak diinginkan, dan iterasi yang lebih cepat.

Halaman ini membahas cara menulis prompt yang efektif, khususnya untuk skenario development menggunakan Mage.

---

## Prinsip dasar prompt

Gunakan kerangka lima bagian berikut sebagai panduan saat menyusun prompt untuk tugas coding:

| Bagian | Pertanyaan yang dijawab | Contoh |
|--------|------------------------|--------|
| **Goal** | Apa yang ingin dicapai? | *Buat halaman Inquiry transaksi* |
| **Context** | File, modul, atau service mana yang relevan? | *`src/app/features/transaction/`, service `TransactionService`* |
| **Constraints** | Apa yang tidak boleh diubah atau ditambahkan? | *Jangan tambah dependency baru, gunakan service yang sudah ada* |
| **Output format** | Apa bentuk keluaran yang diharapkan? | *Satu standalone component + template HTML + interface TypeScript* |
| **Verification** | Bagaimana tahu hasilnya benar? | *Kompilasi bersih, tabel menampilkan data, filter mempersempit hasil* |

Tidak semua prompt memerlukan kelima bagian secara eksplisit. Untuk tugas kecil, cukup **goal + context** sudah jauh lebih baik dari prompt yang kosong.

## Beri anchor, jangan dikte caranya

Qwen3.6 27b bekerja paling baik saat diberi **titik awal yang jelas** - bukan prosedur langkah demi langkah yang Anda tentukan sendiri. Model ini sudah menjalankan loop agentic-nya sendiri (rencanakan → pakai tool → amati hasil → putuskan langkah berikutnya), jadi mendikte urutan langkah biasanya redundan, dan kadang malah bentrok dengan rencana yang sudah dibuat model.

**Anchor yang berguna:**
- Path file: `src/app/shared/components/data-table/`
- Nama modul/service: `AccountModule`, `TransactionService`
- Pesan error: `ERROR: ExpressionChangedAfterItHasBeenCheckedError in transaction-list.component.ts`
- Nama test: `it('should filter by status')`

:::tip[Minimal tapi spesifik]
Prompt singkat yang punya anchor jelas lebih baik dari prompt panjang yang mendiktekan cara berpikir model.

**Kurang efektif:** *"Pikirkan langkah demi langkah. Pertama buka semua file di module ini. Kemudian periksa service-nya. Lalu..."*

**Lebih efektif:** *"Add pagination to `TransactionListComponent`. Service: `TransactionService.getList(page, size)` already exists. Keep template changes minimal."*
:::

## Pola prompt yang efektif

### Membuat fitur baru

```
Create an Inquiry page for [feature name].
Files: [folder/module path]
Use existing [ServiceName] - do not create a new service.
Component must be standalone.
Output: component class, template, and TypeScript interface for the response model.
Success: compiles clean, table renders data rows, filter narrows results.
```

### Perbaikan bug

```
Fix [observed behavior] in [ComponentName].
Expected: [expected behavior].
Relevant files: [file-a.ts], [file-b.html]
Apply the smallest patch that resolves the issue - do not refactor unrelated code.
```

### Refactor

```
Refactor [TargetFile] for readability.
No behavior changes. No API changes. No new dependencies.
Keep all exported function signatures identical.
```

### Tambah fitur ke komponen yang sudah ada

```
Add [feature] to [ComponentName].
Change only files necessary.
Do not rename exported functions or change existing inputs/outputs.
Stop after the minimal working implementation.
```

## Bahasa prompt: English atau Indonesia?

:::tip[Gunakan English untuk prompt teknis/coding]
Anda bebas berbicara dalam Bahasa Indonesia untuk pertanyaan konseptual atau diskusi. Namun untuk prompt yang menghasilkan kode, **English lebih disarankan** karena:

- Sebagian besar data training Qwen untuk kode berbahasa English - istilah teknis, nama API, dan konvensi framework lebih presisi dalam English.
- Nama file, class, dan method sudah dalam English; prompt yang mencampurkan Indonesia dan English cenderung menghasilkan keluaran yang inkonsisten.
- Error message dan dokumentasi Angular/TypeScript juga berbahasa English - lebih mudah di-copy-paste langsung ke prompt.

Gunakan Indonesia hanya jika Anda mendiskusikan pendekatan, bertanya tentang arsitektur, atau meminta penjelasan - bukan saat meminta Mage menulis atau mengubah kode.
:::

## Contoh: membuat fitur Inquiry di Angular

**Skenario:** Anda perlu membuat halaman Inquiry di aplikasi Angular - sebuah halaman berisi form filter di bagian atas dan tabel hasil di bawahnya, misalnya daftar transaksi dengan kolom status, nomor referensi, dan tanggal.

### Prompt lemah

```
buatkan halaman inquiry transaksi di angular
```

Prompt ini tidak memberi informasi tentang module yang digunakan, service yang ada, atau batasan apa pun. Model akan menebak-nebak struktur, kemungkinan membuat service baru yang tidak diperlukan, dan hasilnya mungkin tidak konsisten dengan codebase Anda.

### Prompt kuat

```
Create a standalone Angular component: TransactionInquiryComponent.

Location: src/app/features/transaction/pages/inquiry/
Module context: TransactionModule (already exists)

Use existing TransactionService with method:
  getTransactions(filter: TransactionFilter): Observable<TransactionPage>

TransactionFilter interface (already defined in transaction.model.ts):
  { referenceNo?: string; status?: string; startDate?: string; endDate?: string; page: number; size: number }

Requirements:
- Filter form at the top: reference number (text input) and status (dropdown: ALL, PENDING, SUCCESS, FAILED)
- Results table below with columns: No, Reference No, Status, Amount, Date
- Pagination at the bottom using existing PaginatorModule
- Show loading skeleton while fetching, show empty state if no results

Constraints:
- Standalone component only
- Reuse TransactionService - do not create a new one
- Do not add new npm dependencies
- Keep all existing exports in transaction.module.ts intact

Output:
- inquiry.component.ts
- inquiry.component.html
- Update transaction-routing.module.ts to add route /transaction/inquiry

Success criteria: compiles with no errors, table renders mock rows, filter form narrows results on submit.
```

### Prompt lanjutan (iterasi)

Setelah Mage menghasilkan komponen dasar, Anda bisa meminta perubahan spesifik tanpa menulis ulang seluruh prompt:

```
In TransactionInquiryComponent, add a date-range filter (startDate and endDate) 
using the existing DatePickerComponent from shared/components/.
Keep everything else unchanged.
```

:::note[Iterasi kecil lebih aman]
Minta perubahan satu per satu, bukan sekaligus. Setiap iterasi lebih mudah di-review dan lebih kecil kemungkinan model mengubah bagian yang tidak perlu disentuh.
:::

## Sesi panjang: ulangi batasan penting

Instruksi dan batasan yang Anda berikan di awal sesi bisa "melemah" seiring percakapan yang panjang - model cenderung lebih patuh pada instruksi yang baru saja diberikan dibanding instruksi lama yang sudah tertimbun banyak pesan. Untuk sesi yang berjalan lama atau multi-iterasi:

- Ulangi batasan kritis (misalnya "jangan tambah dependency baru") setiap kali Anda meminta perubahan baru, jangan asumsikan model masih mengingatnya.
- Jangan mengandalkan satu prompt panjang di awal sebagai jaminan perilaku model untuk seluruh sesi.

## Checklist sebelum mengirim prompt

Sebelum menekan Enter, periksa apakah prompt Anda sudah mencakup:

- [ ] **Goal jelas** - satu kalimat yang menggambarkan hasil akhir yang diinginkan
- [ ] **Path file atau nama modul** disertakan sebagai anchor
- [ ] **Service atau dependency yang sudah ada** disebutkan agar tidak dibuat ulang
- [ ] **Batasan** dinyatakan secara eksplisit (jangan tambah X, jangan ubah Y)
- [ ] **Format keluaran** disebutkan jika penting (file apa saja yang diharapkan)
- [ ] **Kriteria sukses** sederhana disebutkan jika hasilnya sulit diverifikasi secara visual
